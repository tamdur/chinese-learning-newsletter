# Mobile Character Lookup — Implementation Plan

## Summary

Add a mobile-only character lookup popup to the newsletter. Long-press (400ms) or single-tap in lookup mode shows a floating tooltip with the character, zhuyin (注音符號), and English definition. Data comes from a per-issue glossary generated by a Haiku subagent and embedded in the HTML.

Desktop is completely unaffected — no CSS changes, no event listeners, Zhongwen works undisturbed.

---

## Architecture

```
Generation Pipeline (new step)
  │
  ├── Haiku subagent: reads finished Chinese text → produces JSON glossary
  │   Keys are single characters AND multi-character words:
  │   { "積": { "zhuyin": "ㄐㄧ", "english": "accumulate" },
  │     "台積電": { "zhuyin": "ㄊㄞˊ ㄐㄧ ㄉㄧㄢˋ", "english": "TSMC" }, ... }
  │
  └── Assembler: embeds glossary as <script>const GLOSSARY = {...}</script>
      in the HTML, just before the main <script> block

Mobile Browser (pointer: coarse)
  │
  ├── Long-press (400ms) on any .c span → popup with zhuyin + definition
  ├── Lookup mode ON → single tap on .c span → popup (fast path)
  └── Flagging mode ON → single tap cycles state (existing, unchanged)

Desktop Browser (pointer: fine)
  │
  └── No changes. Zhongwen extension works normally.
```

**JavaScript additions** (inside the existing IIFE, after the `matchMedia` guard):

```javascript
// === Mobile character lookup ===

const isMobile = window.matchMedia('(pointer: coarse)').matches;

if (isMobile) {
  let lookupMode = false;
  let longPressTimer = null;
  let feedbackTimer = null;
  let startX = 0;
  let startY = 0;
  let activeSpan = null;
  const LONG_PRESS_MS = 400;
  const MOVE_THRESHOLD = 10;

  const popup = document.getElementById('char-popup');
  const popupChar = document.getElementById('popup-char');
  const popupZhuyin = document.getElementById('popup-zhuyin');
  const popupDef = document.getElementById('popup-def');
  const lookupToggleBtn = document.getElementById('lookup-toggle');

  // --- Popup positioning ---

  function positionPopup(targetSpan) {
    const rect = targetSpan.getBoundingClientRect();
    const popupWidth = 280;
    const margin = 8;
    const gap = 6;
    const vw = window.innerWidth;

    // Show popup to measure height
    popup.classList.add('visible');
    const popupHeight = popup.offsetHeight;

    // Horizontal: center on character, clamp to viewport
    let left = rect.left + rect.width / 2 - popupWidth / 2;
    left = Math.max(margin, Math.min(left, vw - popupWidth - margin));

    // Vertical: prefer above the character
    let top = rect.top - popupHeight - gap;
    if (top < margin) {
      top = rect.bottom + gap; // fall back to below
    }

    popup.style.left = left + 'px';
    popup.style.top = top + 'px';
  }

  // --- Longest-match glossary lookup ---
  // Reads adjacent .c spans to find the longest glossary key
  // containing the tapped character. Falls back to single-char lookup.

  function findLongestMatch(targetSpan) {
    if (typeof GLOSSARY === 'undefined') return null;

    // Collect all .c spans in the same parent container
    const parent = targetSpan.closest('p, h2, li') || targetSpan.parentElement;
    const spans = [...parent.querySelectorAll('.c')];
    const targetIdx = spans.indexOf(targetSpan);
    if (targetIdx === -1) return null;

    // Build the full text string + index map
    const chars = spans.map(s => s.textContent);

    // Try substrings of decreasing length that include targetIdx
    // Max word length in Chinese is ~4 characters (practical limit)
    const MAX_WORD_LEN = 6;
    let bestMatch = null;
    let bestSpans = null;

    for (let len = Math.min(MAX_WORD_LEN, chars.length); len >= 1; len--) {
      // Try all windows of this length that include targetIdx
      const startMin = Math.max(0, targetIdx - len + 1);
      const startMax = Math.min(targetIdx, chars.length - len);

      for (let start = startMin; start <= startMax; start++) {
        const candidate = chars.slice(start, start + len).join('');
        if (GLOSSARY[candidate]) {
          if (!bestMatch || candidate.length > bestMatch.length) {
            bestMatch = candidate;
            bestSpans = spans.slice(start, start + len);
          }
        }
      }

      // Stop early if we found a match at this length
      if (bestMatch && bestMatch.length === len) break;
    }

    return bestMatch
      ? { text: bestMatch, entry: GLOSSARY[bestMatch], spans: bestSpans }
      : null;
  }

  function showPopup(char, targetSpan) {
    const match = findLongestMatch(targetSpan);

    if (match) {
      popupChar.textContent = match.text;
      popupZhuyin.textContent = match.entry.zhuyin;
      popupDef.textContent = match.entry.english;
    } else {
      // No match at all — show single char with fallback
      popupChar.textContent = char;
      popupZhuyin.textContent = '';
      popupDef.textContent = '(not in glossary)';
    }

    // Clear previous selection highlight
    document.querySelectorAll('.c.touch-selected').forEach(
      el => el.classList.remove('touch-selected')
    );

    // Highlight all spans in the matched word
    const highlightSpans = match ? match.spans : [targetSpan];
    highlightSpans.forEach(s => s.classList.add('touch-selected'));
    activeSpan = targetSpan;

    positionPopup(targetSpan);
  }

  function hidePopup() {
    popup.classList.remove('visible');
    document.querySelectorAll('.c.touch-selected').forEach(
      el => el.classList.remove('touch-selected')
    );
    activeSpan = null;
  }

  // --- Dismiss handlers ---

  document.getElementById('popup-close').addEventListener('click', hidePopup);

  document.addEventListener('click', function (e) {
    if (!popup.classList.contains('visible')) return;
    if (popup.contains(e.target)) return;
    // If clicking another .c span, showPopup handles it
    if (!e.target.closest('.c')) {
      hidePopup();
    }
  });

  // Dismiss on scroll
  let scrollDismissAttached = false;
  function attachScrollDismiss() {
    if (scrollDismissAttached) return;
    scrollDismissAttached = true;
    window.addEventListener('scroll', function onScroll() {
      hidePopup();
      window.removeEventListener('scroll', onScroll);
      scrollDismissAttached = false;
    }, { once: true });
  }

  // --- Long-press handling ---
  // NOTE: We do NOT call preventDefault on touchstart.
  // CSS user-select: none (scoped to pointer: coarse) handles
  // suppressing native selection. preventDefault would block
  // scrolling from .c spans, which cover most of the viewport.

  document.addEventListener('touchstart', function (e) {
    const span = e.target.closest('.c');
    if (!span) return;

    const touch = e.touches[0];
    startX = touch.clientX;
    startY = touch.clientY;

    // Visual feedback after 100ms
    feedbackTimer = setTimeout(function () {
      span.classList.add('touch-active');
    }, 100);

    longPressTimer = setTimeout(function () {
      span.classList.remove('touch-active');
      showPopup(span.textContent, span);
      attachScrollDismiss();
    }, LONG_PRESS_MS);
  }, { passive: true });

  document.addEventListener('touchmove', function (e) {
    if (!longPressTimer) return;
    const touch = e.touches[0];
    if (Math.abs(touch.clientX - startX) > MOVE_THRESHOLD ||
        Math.abs(touch.clientY - startY) > MOVE_THRESHOLD) {
      clearTimeout(longPressTimer);
      clearTimeout(feedbackTimer);
      longPressTimer = null;
      document.querySelectorAll('.touch-active').forEach(
        el => el.classList.remove('touch-active')
      );
    }
  }, { passive: true });

  document.addEventListener('touchend', function (e) {
    clearTimeout(longPressTimer);
    clearTimeout(feedbackTimer);
    longPressTimer = null;
    const span = e.target.closest('.c');
    if (span) span.classList.remove('touch-active');
  }, { passive: true });

  document.addEventListener('touchcancel', function () {
    clearTimeout(longPressTimer);
    clearTimeout(feedbackTimer);
    longPressTimer = null;
    document.querySelectorAll('.touch-active').forEach(
      el => el.classList.remove('touch-active')
    );
  }, { passive: true });

  // --- Lookup mode toggle ---

  lookupToggleBtn.addEventListener('click', function () {
    lookupMode = !lookupMode;
    this.textContent = lookupMode ? '查詢模式 ON' : '查詢模式 OFF';
    this.classList.toggle('active', lookupMode);

    // Mutually exclusive with flagging mode
    if (lookupMode && flaggingMode) {
      flaggingMode = false;
      document.getElementById('flag-toggle').textContent = '標記模式 OFF';
      document.getElementById('flag-toggle').classList.remove('active');
      document.body.classList.remove('flagging-on');
    }
  });

  // Modify existing flag-toggle handler to deactivate lookup mode
  // (see integration note below)

  // --- Lookup mode: single-tap shows popup ---

  document.addEventListener('click', function (e) {
    if (!lookupMode) return;
    const span = e.target.closest('.c');
    if (!span) return;
    e.stopPropagation();
    showPopup(span.textContent, span);
    attachScrollDismiss();
  });

} // end if (isMobile)
```

**Integration with existing flagging mode toggle:**

The existing flag-toggle click handler needs a small addition — when flagging mode activates, deactivate lookup mode:

```javascript
// Inside existing flag-toggle click handler, add:
if (flaggingMode && lookupMode) {
  lookupMode = false;
  document.getElementById('lookup-toggle').textContent = '查詢模式 OFF';
  document.getElementById('lookup-toggle').classList.remove('active');
}
```

This requires `lookupMode` to be accessible from outside the `if (isMobile)` block. Solution: declare `lookupMode` at the top of the IIFE, initialize to `false`, and let the mobile block manage it. The flagging handler just checks/resets it.

### 2. Generation Pipeline (`scripts/generate_prompt.md`)

**New step between steps 5 and 6:**

#### Step 5.5: Generate character glossary (Haiku subagent)

After writing all Chinese article text and before assembling the HTML, launch a Haiku subagent to build the glossary.

**Input to Haiku:** All the Chinese text from the 5 articles (body text + headlines). Not the English translations.

**Haiku prompt:**

```
You are a Chinese language reference tool. Given the following Traditional
Chinese text, perform word segmentation and produce a JSON glossary with
entries for every meaningful unit — both single characters AND multi-character
words.

Each key is a Chinese string (1 or more characters). Each value is an object:
  - "zhuyin": zhuyin (注音符號) pronunciation. Use standard zhuyin with tone
    marks (ˊ ˇ ˋ ˙). First tone has no mark. For multi-character words,
    separate each character's zhuyin with a space.
  - "english": a concise English definition (1-5 words). Pick the meaning
    most relevant to how the word is used in the text.

Rules:
- Include EVERY unique single character (including common ones: 的, 是, 了)
- Also include every multi-character word that functions as a meaning unit
  in the text (e.g., 台積電, 利率, 宣布, 晶圓廠, 通貨膨脹)
- Proper nouns that are multi-character should be included (e.g., 台積電, 聯準會)
- For polyphonic characters, pick the pronunciation matching usage in context
- Use Traditional Chinese zhuyin conventions
- Do NOT include punctuation (，。「」！？)
- Output valid JSON only, no markdown fencing, no explanation

Example output:
{
  "積": { "zhuyin": "ㄐㄧ", "english": "accumulate" },
  "電": { "zhuyin": "ㄉㄧㄢˋ", "english": "electricity" },
  "台積電": { "zhuyin": "ㄊㄞˊ ㄐㄧ ㄉㄧㄢˋ", "english": "TSMC" },
  "宣布": { "zhuyin": "ㄒㄩㄢ ㄅㄨˋ", "english": "to announce" },
  "利率": { "zhuyin": "ㄌㄧˋ ㄌㄩˋ", "english": "interest rate" }
}

Text:
[paste all Chinese body text here]
```

**Why Haiku, not Opus:**
- This is a mechanical reference/segmentation task, not creative writing — Haiku is sufficient and much cheaper/faster
- Can run in parallel with other assembly steps

**Output format:** Raw JSON. The assembler parses it and embeds it as:

```html
<script>
const GLOSSARY = { /* Haiku's output */ };
</script>
```

**Error handling:** If Haiku returns malformed JSON, log a warning and embed an empty glossary (`const GLOSSARY = {};`). The popup will show "(not in glossary)" for all characters — degraded but functional.

**Glossary size estimate:** ~300 unique characters + ~200 multi-character words × ~90 bytes each ≈ 45KB of JSON. Negligible addition to page size.

## Scrolling Behavior

**No `preventDefault()` on touchstart.** This is critical.

The `.c` spans cover most of the viewport's text area. If we call `preventDefault()` on `touchstart` for `.c` spans, users cannot initiate a scroll by touching article text — they'd have to find whitespace or margins to scroll from. This is a terrible UX.

Instead:
- CSS `user-select: none` (scoped to `@media (pointer: coarse)`) suppresses native text selection and the magnifying loupe
- The long-press timer runs passively; `touchmove` with >10px displacement cancels it
- All touch listeners use `{ passive: true }` so the browser knows scrolling won't be blocked
- On iOS 18 (target device), `user-select: none` fully suppresses native text selection and the magnifying loupe. No trade-offs here.

## Resolved Design Questions

1. **Native selection suppression:** Target is iOS 18 Chrome (WebKit under the hood). `user-select: none` scoped via `@media (pointer: coarse)` fully suppresses the loupe and text selection on iOS 16+. No need for `preventDefault()` on touchstart. `-webkit-touch-callout: none` included as belt-and-suspenders.

2. **Zhuyin accuracy:** At grade-5 reading level, characters are common enough that Haiku handles zhuyin and polyphonic disambiguation from context reliably. No special validation needed.

3. **Multi-character words:** The glossary includes both single-character and multi-character word entries. Haiku performs word segmentation as part of glossary generation. The JS lookup uses a longest-match algorithm — when the user taps a character, it reads adjacent `.c` spans and finds the longest glossary key containing that character. All matched spans highlight together.
